The tables below list every REST endpoint on your server, grouped by area. For a guided start, see [With the API](/docs/printing/api).

## Basics

- Base address: `https://your-print-better.example/api`. Paths in the tables below are relative to it.
- Requests and responses are JSON, except file uploads and downloads.
- `:ws` is a workspace ID. Get yours from `GET /auth/session` or `GET /workspaces`.

## Authentication

Send a personal API token in the `Authorization` header:

```sh
curl https://your-print-better.example/api/workspaces \
  -H "Authorization: Bearer $PRINTBETTER_TOKEN"
```

Create a token under **Your account**, then **Apps and tokens**. See [API tokens](/docs/workspaces/tokens).

Tokens start with `pbt_`. A token can be limited to one workspace and can expire.

The web app uses a session cookie instead. Requests with that cookie that change something must send an `Origin` header that matches the server.

OAuth tokens from AI assistants (`pbo_`) work only with the [MCP server](/docs/reference/mcp). The REST API returns `401` for them.

## Scopes

| Scope | Allows |
| --- | --- |
| `read` | Reading and listing. |
| `print` | Creating, uploading, canceling, retrying, and deleting jobs, and test pages. |
| `write` | Every other change. |

Personal API tokens hold all three scopes. A missing scope returns `403` with the code `insufficient_scope`.

The **Scope** column in the tables also uses these values:

- **session**: The endpoint needs a signed-in browser. Tokens get `403 session_required`.
- **none**: The endpoint needs no sign-in.
- **any**: Any token scope works.

## Roles

Many endpoints also need a role in the workspace:

- Members can read, print, and manage their own jobs.
- Admins and owners can change printers, devices, members, and settings.

The tables mark these endpoints with **Admins** or **Owners**. **Server admins** are the accounts that can open **Server admin**.

With the [Printer access](/docs/extensions/printer-access) extension active, each printer's permissions replace the admin rule for printers and jobs. Printers and jobs you can't see are left out of lists and return `404`.

## Errors

Errors use the HTTP status and a JSON body:

```json
{ "error": { "code": "printer_required", "message": "Choose a printer (this workspace has no default printer)" } }
```

| Status | Common codes |
| --- | --- |
| `400` | `invalid_request`, `printer_required`, `size_mismatch`, `email_disabled` |
| `401` | `unauthorized`, `invalid_token`, `invalid_credentials` |
| `403` | `forbidden`, `insufficient_scope`, `session_required`, `bad_origin`, `printer_access_denied` |
| `404` | `not_found`, `extension_inactive` |
| `409` | `conflict`, `client_offline`, `printer_not_added`, `job_finished`, `job_not_retryable`, `file_purged`, `last_owner` |
| `413` | `too_large` |
| `415` | `unsupported_type` |
| `429` | `rate_limited` |

## Pagination

`GET /workspaces/:ws/jobs` and `GET /workspaces/:ws/audit` return pages, newest first:

```json
{ "items": [], "nextCursor": "MTc2..." }
```

Pass `?limit=` for the page size (50 by default, 200 at most). Pass `nextCursor` back as `?cursor=` to get the next page. When `nextCursor` is `null`, there are no more pages.

## Two-step upload

Send small documents inline as `text`, `url`, or `base64`. For larger files, create the job first and then upload the file.

<Steps>

### Create the job

```sh
curl -X POST https://your-print-better.example/api/workspaces/$WS/jobs \
  -H "Authorization: Bearer $PRINTBETTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"printerId":"'$PRINTER'","upload":{"fileName":"report.pdf","contentType":"application/pdf","size":182044}}'
```

The response holds the job, with status `uploading`, and an absolute `uploadUrl`.

### Upload the file

```sh
curl -X PUT "$UPLOAD_URL" \
  -H "Authorization: Bearer $PRINTBETTER_TOKEN" \
  -H "Content-Type: application/pdf" \
  --data-binary @report.pdf
```

The `Content-Type` must match the declared type, or you get `415 unsupported_type`. The body must be exactly `size` bytes, or you get `400 size_mismatch`. The job then moves to `queued`.

</Steps>

Uploads have these limits:

- Types: `application/pdf`, `image/jpeg`, `image/png`, and `text/plain`.
- Size: The workspace's upload limit, 50 MB by default.
- Time: An upload that never finishes fails after an hour.

Job options are listed in [Job options](/docs/reference/job-options).

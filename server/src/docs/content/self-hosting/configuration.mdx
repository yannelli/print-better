Every server setting is in one of three places: the Cloudflare configuration in `wrangler.jsonc`, the Worker secrets, or **Server admin**.

## Where settings live

| Setting | Where | Who changes it |
| --- | --- | --- |
| Cloudflare bindings, schedule, custom domain | `server/wrangler.jsonc` | You, then deploy again |
| `SETUP_TOKEN`, `APP_SECRET`, `AUTH_PEPPER` | Worker secrets | You, with `wrangler secret put` |
| Server name, sign-up, sign-in, email, extensions | **Server admin**, saved in D1 | Server admins |
| Printer, job, and email rules for one workspace | **Workspace settings**, saved in D1 | Workspace owners and admins |

Workspace settings are covered in [Workspace settings](/docs/workspaces/settings).

## wrangler.jsonc

```jsonc title="wrangler.jsonc"
{
  "name": "print-better",
  "d1_databases": [{ "binding": "DB", "database_name": "print-better", "migrations_dir": "migrations" }],
  "r2_buckets": [{ "binding": "FILES", "bucket_name": "print-better-files" }],
  "durable_objects": { "bindings": [{ "name": "HUB", "class_name": "WorkspaceHub" }] },
  "triggers": { "crons": ["*/15 * * * *"] },
  "vars": { "APP_NAME": "Print Better" }
}
```

The full file has a few more keys, such as `assets` and `observability`. The table describes those too.

| Key | Default | Purpose |
| --- | --- | --- |
| `name` | `print-better` | The Worker's name. Email Routing sends mail to this Worker. |
| `d1_databases` | `DB` bound to `print-better` | Accounts, workspaces, devices, printers, jobs, tokens, and settings. |
| `r2_buckets` | `FILES` bound to `print-better-files` | Print documents and client downloads. |
| `durable_objects` | `HUB`, class `WorkspaceHub` | One hub per workspace that holds the device connections. |
| `triggers.crons` | Every 15 minutes | Runs the cleanup tasks below. |
| `vars.APP_NAME` | `Print Better` | The server name until a server admin sets **Name** in **Server admin**. |
| `observability` | On | Sends Worker logs to Cloudflare Workers Logs. |
| `assets.run_worker_first` | API, MCP, OAuth, install, and download paths | Paths the Worker answers. Every other path serves the web app. |

Two keys are optional and absent by default:

| Key | Add it to |
| --- | --- |
| `routes` | Serve the server on your own domain. See [Use your own domain](/docs/self-hosting/deploy#use-your-own-domain). |
| `send_email` | Send email through Cloudflare. Add `"send_email": [{ "name": "EMAIL" }]`. See [Email](/docs/self-hosting/email#send-with-cloudflare). |

Run `scripts/deploy.sh` after any change to this file.

## Secrets

| Secret | Purpose |
| --- | --- |
| `SETUP_TOKEN` | Must match the setup code to create the first account. |
| `APP_SECRET` | Key for the AES-GCM encryption of stored secrets, such as SSO client secrets and the Resend API key. |
| `AUTH_PEPPER` | Server-wide secret mixed into every password hash and recovery code. |

The deploy script creates all three. See [Secrets](/docs/self-hosting/deploy#secrets) for what happens if you lose one.

For local development, copy `server/.dev.vars.example` to `server/.dev.vars` and fill in the three values.

## Server admin

Server admins see **Server admin** in the sidebar. The first account on the server is a server admin. The page has five tabs.

### General

- **Name**: Shown on the sign-in page and in emails.
- **Who can create an account**: **Only people with an invite link** (the default) or **Anyone with the address**. With the second choice, new people can sign up and make their own workspace.

Select **Save changes** after you edit either one.

### Sign-in options

Turns on Google sign-in and sign-in with any OpenID Connect provider. See [Sign-in](/docs/self-hosting/sign-in).

### Email

Sets up sending email and receiving email to print. See [Email](/docs/self-hosting/email).

### People

**Everyone on this server** lists every account. For each person you can:

- Select **Make admin** or **Remove admin**. Server admins can change sign-in, email, and sign-up settings, and manage every account.
- Select **Reset password** to get a one-time link to send them.
- Select **Delete account**. They are removed from every workspace and can't sign in again.

The server always keeps at least one server admin.

You can't delete someone who is the only owner of a workspace. Transfer or delete that workspace first.

### Extensions

Makes optional features available to workspaces. See [Extensions](/docs/extensions).

## Scheduled cleanup

Every 15 minutes the Worker:

- Deletes stored documents of finished jobs older than each workspace's **Keep documents for** time.
- Deletes expired sessions, sign-in challenges, setup codes, device codes, API and OAuth tokens, and unused invites.
- Deletes OAuth app registrations older than 30 days that have no tokens.
- Marks uploads that never finished after an hour as failed.
- Marks jobs with no progress for the workspace's **Keep trying for** time as failed.
- Marks devices offline when their connection is gone.

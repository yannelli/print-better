Your server can send email and receive email. Both are optional and off by default.

- Sending email delivers invites, reset links, and printer alerts.
- Receiving email lets people print by sending a document to a printer's own address.

## Without Email

The server works without email. Without it:

- Invites are links you copy and send yourself.
- People reset a password with a recovery code, or a server admin gives them a reset link.
- People can't verify their email address.
- Email to print is not available.

## What the Server Sends

| Email | Sent to | When |
| --- | --- | --- |
| Invite | The invited address | An admin invites someone and enters their email. |
| Password reset | The account's email | Someone uses **Email me a reset link**. The link works for 1 hour. |
| Email verification | The account's email | After sign-up with an email, after an email change, or from **Send verification email**. The link works for 24 hours. |
| Printer alert | Workspace owners and admins who have an email | An added printer needs a person, for example it is out of paper, jammed, or out of toner. At most once per printer every 12 hours. |

## Set up Sending

1. Open **Server admin**, then **Email**.
2. Under **Sending email**, choose a provider in **How to send email**.
3. Enter **Send from**, for example `Print Better <print@example.com>`. The address must belong to a domain you set up with your email provider.

## Send With Resend

<Steps>

### Prepare Resend

In Resend, verify your domain. Create an API key with sending access.

### Enter the Key

Choose **Resend**. Enter **Send from** and paste the **Resend API key**. Select **Save changes**.

</Steps>

## Send With Cloudflare

<Steps>

### Prepare Your Domain

In the Cloudflare dashboard, set up your domain for Email Sending.

### Add the Binding

Add this line to `server/wrangler.jsonc`, then run `scripts/deploy.sh`:

```jsonc title="wrangler.jsonc"
"send_email": [{ "name": "EMAIL" }]
```

### Choose Cloudflare

Choose **Cloudflare Email**. Enter **Send from** and select **Save changes**. The server refuses to save this choice until the `EMAIL` binding exists.

</Steps>

## Set up Email to Print

Email to print needs 3 things turned on:

- The server receives mail.
- A workspace allows it.
- A printer has an address.

## Receive With Cloudflare Email Routing

<Steps>

### Route the Mail to the Worker

In the Cloudflare dashboard, turn on Email Routing for your domain. Add a catch-all rule, or 1 rule per address, with the action **Send to a Worker** and the Worker `print-better`.

### Choose Email Routing in Server Admin

In **Server admin**, then **Email**, go to **Receiving email**. Under **How email arrives**, choose **Cloudflare Email Routing**. Enter the **Email domain for printers**, for example `print.example.com`, and select **Save changes**.

</Steps>

## Receive With Resend

<Steps>

### Enter the Resend API Key

Resend receiving uses the API key from sending. Under **Sending email**, choose **Resend** and enter the **Resend API key**.

### Set up a Receiving Domain in Resend

Add Resend's MX records for the domain that will receive mail. Add a webhook for the `email.received` event with this address:

```text
https://your-print-better.example/api/hooks/resend
```

**Server admin** shows it as **Webhook address to give Resend**.

### Choose Resend in Server Admin

Under **How email arrives**, choose **Resend**. Enter the **Email domain for printers**.

Paste the **Webhook signing secret** from Resend. It starts with `whsec_`. Select **Save changes**.

</Steps>

## Turn It On for a Workspace and a Printer

1. In **Settings** > [**Email to print**](/settings/email), turn on **Allow printing by email**. Choose who may send. See [Workspace Settings](/docs/workspaces/settings).
2. On a printer's page, under **Sharing**, turn on **Print by email**. Enter an **Email name for this printer**, such as `kitchen`, and select **Save name**.

People then send documents to that name at your printer domain, for example `kitchen@print.example.com`. See [By Email](/docs/printing/email).

## What Prints

- Attachments in PDF, JPEG, PNG, or plain text, up to 10 per message.
- Inline images, such as logos in a signature, are skipped.
- Each attachment must fit the workspace's upload limit.
- A message with no printable attachment prints its text body instead.

## Which Mail Is Refused

The server refuses a message when:

- It fails DMARC. With Cloudflare, the server trusts only the first `Authentication-Results` header, from `mx.cloudflare.net`. With Resend, it uses Resend's verdict.
- The sender isn't allowed. A member must send from the verified email on their account, with **Accept email from members** on. Anyone else must be on the workspace's list.
- No added printer has that address with **Print by email** on, in a workspace that allows it.
- Nothing in the message can print.

With Cloudflare Email Routing, the server rejects the message, so the sender gets a bounce with the reason. With Resend, the reason appears in the Worker's logs. See [Email to Print Is Refused](/docs/reference/troubleshooting#email-to-print-is-refused).

With the [Printer Access](/docs/extensions/printer-access) extension active, a member also needs permission to print to that printer. Senders who aren't members can print only where Everyone may print.
